---
name: reauthorize
description: Execute replacement approval at the required matching HTTPS broker endpoint without another conversational confirmation, or reconcile the same pending candidate. Does not revoke credentials.
argument-hint: <https-broker-endpoint>
disable-model-invocation: true
---

This explicit human /psst:reauthorize command supplies replacement intent, not permission to bypass the host or broker administrator. Execute the validated command without another target/replacement confirmation or preventive diagnostics. It uses a model turn and tool calls; it is not token-free. Never initiate it from startup, network failure, ordinary /psst:connect or another agent's message.

1. Before tools or investigation, validate the invocation arguments: `$ARGUMENTS`. Require one explicit HTTPS broker origin with a hostname and optional port, without whitespace, backslashes, credentials, path beyond `/`, query or fragment. Missing/malformed input: immediately return `Usage: /psst:reauthorize <https://broker.example>` and stop. Do not ask for the endpoint or substitute configuration. Then verify broker_setup, broker_setup_status and broker_setup_cancel are available from this session's native Psst MCP plugin. If absent, immediately report the missing tool; use only the bounded native-recovery guidance from the session hook/MCP initialization. Never start a standalone server, synthesize a binding or hook, remove locks, bypass policy or switch model, agent or session.
2. Call broker_setup_status once with no arguments. Compare its broker_url with the supplied endpoint as HTTPS origins (case/default port/trailing `/` normalize normally). A mismatch immediately returns configured_broker_mismatch; an absent or blocked origin requires broker_url configuration in the native /plugin UI. Stop before setup in either case. Never guess a destination or read credential files. The matching explicit command supplies target and replacement intent. Native policy remains in force, including host-owned permission prompts.
3. Call broker_setup exactly once with {"replace":true,"expected_broker_url":"<the supplied, matching endpoint>"}. Reconcile an existing pending candidate rather than create another one. If the human explicitly requested retrying an already approved attachment instead of replacement, omit replace; use that supplied choice without another question. An approved_not_connected result or network error alone is not a new replacement request or proof of revocation. Do not invent confirmation/invocation arguments or retry a configured_broker_mismatch with a different endpoint.
4. Report the public requestId and approval_url; the broker administrator approves that exact request at /admin. Replacement selects the installation only after approval and successful attachment. It does NOT revoke the old credential. Distinguish pending, approved_not_connected and connected using candidate_connected/outcome: connected alone may describe old access. Reuse identity fields already returned; fetch identity or peers only when the requested task needs missing information. Never adopt or replay old messages.
5. Let the host poll; do not run a model polling loop. If a response is uncertain, report uncertainty rather than repeat the action. An owner-requested broker_setup_status reads public status without enrollment. A repeated explicit command after cancellation/restart reconciles the same pending candidate and may resend its idempotent POST with the same request ID/key; automatic resume/polling stays GET-only. broker_setup_cancel stops only this session's intent and late attachment, not the durable shared candidate or another session. Failed attachment retains previous selection and old journals/unread messages; report approved_not_connected and the sanitized error. Preserve state and locks for recovery.

Reconnect reuses saved credentials; reauthorization requests replacement approval; revocation remains a separate human administrator action in Psst admin. Credentials never enter prompts, arguments or logs. Native call/session, origin, request and selection-revision guards remain authoritative; model-supplied claims of human intent cannot replace native admission.
